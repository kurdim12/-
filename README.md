# Sehha-GIS · صحة جي‑آي‑إس

**National Health Intelligence Layer for Jordan** — a bilingual EN/AR dashboard that turns Hakeem patient-record data into three decision lenses: hospital capacity planning, disease surveillance + 12-month forecasting, and specialist access gaps.

> Submitted to **HAAC 2026** (Hakeem Academy Annual Competition, EHS Jordan)
> Author: **Abdelrahman Elkurdi**

---

## What it does

Three modules over twelve governorates, with a national overview that toggles all three layers on one Jordan map:

1. **Hospital Capacity Planning** — choropleth of beds per 1,000 with under / balanced / over labels and a ranked investment-priority table.
2. **Disease Surveillance & Forecasting** — incidence heatmap by condition, 12-month Prophet-shaped forecasts with 95% CI, and a watch-list of governorates above 2σ from baseline.
3. **Specialist Access Gaps** — specialists per 100k by specialty with a Travel Burden Index for each region.

Full RTL support, government-grade clinical aesthetic, no backend.

## Stack

- **Next.js 14** (App Router) — static export, edge-ready
- **Tailwind CSS** — styling + RTL via `ms-*` / `me-*`
- **Leaflet + react-leaflet** — choropleth maps, client-only via dynamic import
- **Recharts** — forecast charts with CI band
- **lucide-react** — iconography
- **Cloudflare Pages** — deploy target via `@cloudflare/next-on-pages`

All data is static TypeScript files; no database, no API. The demo works instantly on any device.

## Build & deploy to Cloudflare Pages

The app builds as a fully static export (`next.config.mjs` has `output: "export"`), so it deploys to Cloudflare Pages with **no edge runtime, no adapter, no surprises**.

### Option A — Deploy from your machine (fastest)

```bash
npm install
npm run build           # produces out/
npm run pages:deploy    # ships out/ to Cloudflare Pages
```

### Option B — Connect the GitHub repo to Cloudflare Pages

In the Cloudflare dashboard, when creating the Pages project, set:

| Field                  | Value                                              |
|------------------------|----------------------------------------------------|
| Framework preset       | **None** (don't pick Next.js — we use static export) |
| Build command          | `npm run build`                                    |
| Build output directory | `out`                                              |
| Node version (env var) | `NODE_VERSION=22`                                  |

Pages will then build on every push to the connected branch.

> Note: `wrangler.toml` already declares `pages_build_output_dir = "out"`, but the **build command itself must be set in the Pages dashboard** — Cloudflare Pages doesn't read build commands from `wrangler.toml`.

### Local preview of the production build

```bash
npm run build
npm run start        # serves out/ on http://localhost:3000
# or:
npm run pages:preview
```

## Methodology (synthetic data)

- **Capacity** figures are hand-tuned to match published Jordanian distributions (Amman well-balanced, southern governorates and Mafraq under-capacity).
- **Forecasts** are generated by a deterministic seasonal decomposition (baseline + linear trend + cosine seasonality + small reproducible noise) and reported with a widening 95% confidence band — the same shape Prophet/ARIMA produce.
- **Specialists** are calibrated to ~80% Amman concentration for cardiology, oncology, and neurology, and a more even pediatrics distribution.

This is a hackathon prototype. Real deployment would integrate live Hakeem data, formal model validation, and clinical review.

## i18n / RTL

- All UI copy lives in `data/translations.ts`.
- Language toggle persists to `localStorage`.
- `<html dir="rtl" lang="ar">` switches on toggle; Tailwind `ms-*` / `me-*` are used throughout instead of `ml-*` / `mr-*`.
- Map zoom controls and labels flip correctly under RTL.

## Limitations

This is a demo. Synthetic data only. The GeoJSON boundaries are simplified polygons recognizable as Jordan's 12 governorates — not survey-grade shapes. The forecast model is a simple seasonal decomposition; a production deployment would use Prophet, NeuralProphet, or a hierarchical Bayesian model with cross-validation.
